# Feature Specification: 游戏道具系统

**Feature Branch**: `[002-game-item-system]`

**Created**: 2026/06/06

**Status**: Draft

**Input**: User description: "再增加一个spec，用来增加系统的道具系统，你按照一般RPG游戏的道具系统进行设计，但应该是一个简化版的，不要太多杂七杂八的功能"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 查看与管理背包 (Priority: P1)

玩家打开背包界面，查看当前拥有的所有道具，支持按道具类型筛选和排序，并能对道具进行基础操作（使用、装备、丢弃）。

**Why this priority**: 背包是道具系统的核心入口，几乎所有道具相关操作都从这里开始。

**Independent Test**: 可以独立测试通过模拟玩家获取多种道具后打开背包，验证列表展示、筛选排序和容量计算均正确。

**Acceptance Scenarios**:

1. **Given** 玩家拥有10种不同类型的道具，**When** 玩家打开背包查看全部道具，**Then** 系统按获得时间倒序展示所有道具及其数量
2. **Given** 玩家拥有消耗品和装备，**When** 玩家选择"仅看装备"筛选，**Then** 系统只展示装备类道具
3. **Given** 玩家背包当前有45个格子被占用（每格容量上限99），**When** 玩家查看背包信息，**Then** 系统正确显示"45/200"

---

### User Story 2 - 使用消耗品 (Priority: P1)

玩家在背包中选择消耗类道具（如生命药水、魔法药水）进行使用，系统立即生效道具效果并扣除对应数量。

**Why this priority**: 消耗品是战斗和探索中最频繁使用的道具类型，直接影响玩家生存和续航能力。

**Independent Test**: 可以独立测试通过模拟玩家在不同血量状态下使用药水，验证属性变化和道具扣除准确。

**Acceptance Scenarios**:

1. **Given** 玩家当前生命值为50/100且拥有3瓶小型生命药水（效果：恢复30点生命），**When** 玩家使用1瓶药水，**Then** 玩家生命值变为80/100，药水数量减少为2瓶
2. **Given** 玩家当前生命值为90/100，**When** 玩家使用恢复30点生命的药水，**Then** 玩家生命值变为100/100（不超过上限），药水数量正确扣除
3. **Given** 玩家拥有1瓶药水，**When** 玩家使用后该道具数量变为0，**Then** 系统从背包中移除该道具条目

---

### User Story 3 - 穿戴与卸下装备 (Priority: P1)

玩家在背包中选择装备类道具进行穿戴，系统根据装备部位自动替换或禁止重复穿戴；玩家也可以主动卸下已穿戴的装备回背包。

**Why this priority**: 装备系统直接关系到角色属性和战斗力成长，是RPG的核心养成要素之一。

**Independent Test**: 可以独立测试通过模拟玩家穿戴和卸下不同部位的装备，验证属性加成变化和背包格子占用情况。

**Acceptance Scenarios**:

1. **Given** 玩家已穿戴一把攻击+10的铁剑，背包中有一把攻击+15的钢剑，**When** 玩家选择穿戴钢剑，**Then** 系统自动卸下铁剑放回背包，玩家攻击力按钢剑属性重新计算
2. **Given** 玩家已穿戴一枚戒指（饰品部位），**When** 玩家尝试穿戴第二枚同样限定为"戒指部位"的装备且该游戏不支持双戒指，**Then** 系统提示该部位已有装备，并询问是否替换
3. **Given** 玩家身上穿戴了一件防具，**When** 玩家选择卸下该防具，**Then** 系统将该装备放回背包，玩家防御力扣除对应加成

---

### User Story 4 - 获得与丢弃道具 (Priority: P1)

玩家通过击杀怪物、完成任务、交易等途径获得新道具，系统正确进入背包；玩家也可以主动丢弃不需要的道具。

**Why this priority**: 道具的流入和流出是维持经济平衡和玩家体验的基础，必须与背包管理无缝衔接。

**Independent Test**: 可以独立测试通过模拟多种获得和丢弃场景，验证堆叠逻辑、背包满格处理和数量变化。

**Acceptance Scenarios**:

1. **Given** 玩家背包已有小型生命药水（数量50，堆叠上限99），**When** 玩家获得20瓶同类型药水，**Then** 系统将该格数量更新为70，不额外占用背包格子
2. **Given** 玩家背包已满（200/200）且没有可合并的堆叠，**When** 玩家尝试获得新道具，**Then** 系统提示背包已满，新道具无法进入背包（可由后续邮件或掉落地面机制处理，本系统仅保证拒绝入库）
3. **Given** 玩家拥有5瓶药水在同一格，**When** 玩家选择丢弃3瓶，**Then** 该格数量变为2瓶，不删除整条记录
4. **Given** 玩家拥有1个已绑定的任务道具，**When** 玩家尝试丢弃，**Then** 系统提示该道具已绑定，无法丢弃

---

### User Story 5 - 管理道具配置 (Priority: P2)

游戏管理员通过管理接口查询现有道具定义、创建新道具、修改已有道具属性或删除未使用的道具定义。

**Why this priority**: 管理功能支撑运营内容更新，但日常频率低于玩家侧操作，因此定为P2。

**Independent Test**: 可以独立测试通过管理接口的增删改查操作，验证道具定义持久化和后续玩家获取行为一致。

**Acceptance Scenarios**:

1. **Given** 管理员填写完整的道具信息（名称、类型、品质、效果/属性、堆叠上限），**When** 管理员提交创建请求，**Then** 系统持久化新道具定义
2. **Given** 管理员修改某装备的基础攻击力，**When** 提交更新后，**Then** 已穿戴该装备的玩家属性即时按新配置重新计算
3. **Given** 管理员查询道具列表，**When** 按"消耗品"类型和"稀有"品质筛选，**Then** 系统返回符合条件的道具定义列表

---

### Edge Cases

- 玩家同时穿戴和卸下同一装备，或网络延迟导致重复请求，系统如何保证数据一致性？
- 玩家获得大量可堆叠道具（如999个），超出单格堆叠上限时，系统如何分配到多个格子？
- 玩家使用最后一个消耗品的同时触发另一个自动消耗逻辑（如战斗自动喝药），是否会导致负数数量？
- 管理员删除一个已有玩家持有的道具定义，这些玩家的背包中该道具如何展示？
- 玩家背包接近满格时获得多个不同种类的道具，部分能堆叠、部分不能，系统如何处理部分成功入库？

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须支持查询玩家背包中的道具列表，支持按道具类型（消耗品/装备/材料/任务道具）筛选
- **FR-002**: 系统必须支持消耗品的使用，使用后立即生效配置的效果（如恢复生命值、恢复魔法值、临时增益属性），并扣除对应数量
- **FR-003**: 系统必须支持装备的穿戴和卸下，每个装备有明确的穿戴部位（武器/头盔/护甲/饰品等），同一部位通常只能穿戴一件
- **FR-004**: 系统必须支持道具的堆叠机制，同类可堆叠道具在同一背包格中累积数量，数量不能超过该道具定义的堆叠上限
- **FR-005**: 系统必须支持玩家获得新道具，优先尝试合并到已有堆叠，无法合并则占用新格子；背包无空余格子时拒绝入库
- **FR-006**: 系统必须支持玩家主动丢弃道具，丢弃后从背包中扣除对应数量；已绑定的道具不允许丢弃
- **FR-007**: 系统必须支持查询道具的详细定义信息，包括名称、描述、类型、品质、图标、效果/属性、堆叠上限
- **FR-008**: 系统必须支持管理员创建、修改、删除道具定义；删除操作仅对未被任何玩家持有的道具生效
- **FR-009**: 系统必须在玩家穿戴装备时，实时计算并应用装备属性到玩家角色；卸下时实时移除对应属性加成
- **FR-010**: 系统必须支持按多种条件查询道具定义，包括但不限于：道具名称（模糊匹配）、类型、品质、等级要求

### Key Entities *(include if feature involves data)*

- **道具定义（ItemDefinition）**: 代表游戏中一种道具的模板配置，包含名称、描述、类型、品质、堆叠上限、图标资源、使用效果和装备属性等
- **玩家道具（PlayerItem）**: 代表某位玩家背包中的一格道具记录，包含关联的道具定义ID、当前数量、是否绑定、获得时间
- **装备属性（EquipmentStats）**: 定义装备类道具提供的角色属性加成，如攻击力、防御力、生命值上限等
- **消耗品效果（ConsumableEffect）**: 定义消耗品使用后的效果，包含效果类型（恢复/增益）和目标属性（生命/魔法/攻击等）
- **穿戴槽位（EquipSlot）**: 定义角色可装备的部位枚举，如主手、头部、身体、饰品等

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 玩家可以在2秒内打开背包并看到完整的道具列表（200格以内）
- **SC-002**: 玩家使用消耗品后，效果在500毫秒内生效并同步到玩家状态
- **SC-003**: 玩家穿戴或卸下装备后，角色属性在1秒内完成重新计算并生效
- **SC-004**: 系统支持至少1000名并发玩家同时进行道具查询和使用操作而不出现明显延迟
- **SC-005**: 背包的道具堆叠逻辑正确率达到100%，不会出现超堆叠或丢失道具的情况
- **SC-006**: 管理员创建或修改道具定义后，该变更在30秒内对所有在线玩家生效

## Assumptions

- 玩家认证和会话管理由现有系统提供，道具系统仅处理已认证玩家的请求
- 背包总格子数固定为200格，暂不支持扩展背包功能
- 道具品质分为：普通、优秀、稀有、史诗、传说，共5个等级
- 装备部位在V1版本中仅支持4个基础部位：武器、头盔、护甲、饰品
- 消耗品效果在V1版本中仅支持即时恢复类（生命/魔法）和短期增益类（攻击/防御），不支持持续回血等复杂机制
- 道具系统需要对接任务系统（任务奖励发放）和经济系统（购买/出售），但交易、拍卖、邮件等高级流转机制不在本版本范围内
- 道具图标资源由客户端管理，服务端仅存储图标标识符
